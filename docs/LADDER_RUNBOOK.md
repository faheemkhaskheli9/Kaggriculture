## The loop

### Phase A — is the pending sub ready to judge?

```bash
python download_episodes.py --submissions 56055430 --refresh
python tools/ladder_analyze.py 56055430
```

- **< 20 episodes** → not ready. Go to Phase C (build, don't submit).
- **Silent all-PASS in early logs** (grep the `*.logs.json` for a bare PASS
  fallback / traceback) → the sub is raising. Kill it: flag OFF, note in
  LEDGER, next queued change.
- **≥ 20 episodes** → Phase B.

### Phase B — judge on the gate metric

Gate = **win-rate (score-rate) vs `animal_factory`**, from `ladder_analyze.py`'s
per-archetype block, compared against the same row for `56044961`.

- **≥ baseline** → keep the flag ON. Promote the candidate file to `main.py`
  verbatim, commit, update State + `experiments/LEDGER.md`. Pending → board-best.
- **< baseline** → flag OFF, retire the candidate to `agents/`, update LEDGER.
- Either way → Phase C for the next change.

### Phase C — build the next flagged candidate (slot-free)

1. **Teardown** the current board-best's losses:
   ```bash
   python download_episodes.py --submissions 56044961 --refresh
   python tools/ladder_analyze.py 56044961          # loss buckets, lead-flip day
   python download_top_replays.py --top 10
   python tools/analyze_top.py --detail             # top agents' move% / hands / cadence
   ```
2. Pick **one mechanical gap** (movement %, market-order-slot priority, idle
   hands, routing detours). **Not** an economy/crop idea — those don't gate.
3. Implement behind `ENABLE_<NAME>` (default OFF) + named config. New file
   `agents/main_v<NN>_<name>.py`; mirror the hunk into `main.py` only on promote.
4. Local gate — regression check only:
   ```bash
   python compete.py --agent agents/main_v<NN>_<name>.py --games 120
   python tools/analyze_runs.py            # must not tank vs starter/random
   ```
5. Commit. Add to State "Next queued change". **Do not submit** — wait for the
   pending read (Phase A) to clear first.

### Phase D — submit (AUTO 2026-09-09; ≤4 experiment/day as 2 batches of 2 ~12h apart, ≤5 total/day)

Auto-submit is granted for locally-gated candidates — no per-submission user
approval. Preconditions, all required:

- Local gate clean: never-raise + **0 `agent()` errors** + no regression vs
  `animal_factory` win-rate (OFF-path zero-diff for the flag + ON 120g).
- Caps: ≤4 experiment-agent subs/day, released as **2 batches of 2, batches
  ~12h apart** (Kaggle tracks only the latest 2); ≤5 total/day.
- **Rating-floor guard:** do NOT submit if it would leave both tracked Kaggle
  slots below the all-time peak (605.1 / `56044961`) with no candidate proven
  better at ≥20 eps. A bytes-identical peak resubmit is allowed to recover.
